# Cross-cutting skill mechanics: feedback vs C-Skills (v0.6.2, worktree `cskills-local`)

Sources: `anthropics__claude-code__skills.json` (235 issues, primary), the other repo dumps, and `hn.json`. All issue text was treated as data. Scripts are in `analysis/` (`mech_titles.py`, `mech_bodies.py`, `mech_thread.py`, `mech_grep.py`, `mech_names.py`, `mech_valprobe.py`), and every one was run with `python -I`. About 60% of the 235 issues are off-topic for skill mechanics (hooks, desktop UI, classifiers, plan mode), so they are excluded below. CC = anthropics/claude-code. "Open" is the state when the data was captured.

## 3. Proposed minimal edits

1. **Frontmatter for `handoff` and `spec`**: drop the angle brackets. Use `docs/handoffs/DATE-TOPIC.md` and `docs/specs/TOPIC.md`, or "a dated file in docs/handoffs/". The bodies can keep `<topic>`. Evidence: #80469, the #26254 upload rules.
2. **Validator: XML-tag check** on `description` and `when_to_use`: `re.search(r"<[A-Za-z/!][^>]*>", text)` gives "description contains an XML-like tag (rejected by API/claude.ai upload)". Evidence: #80469, #26254.
3. **Validator: `$N` guard** on the body: `re.search(r"(?<!\\)\$\d", body)` gives "unescaped $N is replaced by args; write \\$N". Evidence: #79859, #91957, #94065, #94496, #94709.
4. **Validator: strict booleans.** Check the raw line `^disable-model-invocation:\s*(true|false)\s*$` instead of relying on the YAML 1.1 bool. Do the same for `user-invocable`.
5. **Validator: exact filename.** Require `"SKILL.md" in os.listdir(d)` so case-insensitive Windows matches cannot hide a bad name. Evidence: #85786.
6. **Validator: refresh `RESERVED`** with `verify, dataviz, schedule, claude-api, deep-research, update-config, keybindings-help, fewer-permission-prompts, workflow-authoring, plugin-authoring, claude-in-chrome`, all present in the current CC skill list.
7. **Validator: warn only** if `~/.claude/skills/<name>/SKILL.md` exists and differs from the repo copy, because the personal copy overrides the project one (#89207, #93075). Do not fail CI for this.
8. **README and test procedure (no code change):**
   - (a) Run activation or behaviour tests from a session **launched** in the checkout under test, then confirm the listing text matches, because worktree sessions read the main checkout (#88931, #100497, reproduced here).
   - (b) Manual skills: type `/name` at the start of a message, and only one per message (#93761, #95469, #78523).
   - (c) With many installed skills, descriptions can go name-only. Point users at `skillListingBudgetFraction` or `skillOverrides` (#81081 maintainer reply).
   - (d) Name overlap with mattpocock/skills, addyosmani/agent-skills, gstack and pstack: personal copies win.
9. *Optional:* a `.gitattributes` with `*.md text eol=lf`. It is not needed for loading, but it keeps the bytes the same across platforms.

## 4. Non-issues for us (checked)

- **CRLF and bare CR**: the validator and Claude Code both handle them (tested).
- **Folded or literal block-scalar descriptions**: parse fine; the hypothesis in #81081 was retracted.
- **Unindented multi-line descriptions, tabs, and an unquoted `: `**: the validator already catches all three.
- **Description length and caps**: all 13 are within 40–500 characters; diagnose's description plus `when_to_use` is 784, well under 1,536.
- **Name format and reserved words**: kebab-case, no "claude" or "anthropic", no clash with built-ins.
- **Description semantics of manual skills**: confirmed as documented (#87536). The validator's "manual skills need no trigger clause" rule is correct.
- **Bugs in `model`, `effort`, `allowed-tools`, `paths`, `context` and `arguments`**: we use none of these fields.
- **Skills packaged as SKILL.md only, so other files are dropped on upload** (#26254, #87898, #100151): all our skills are single-file.
- **Nested discovery depth** (#88400): our skills are one level deep.
- **Over-triggering wording** (superpowers #2423 and others): not present in our files.
- **Missing listing, duplicated catalog, `/context` accounting, background and VS Code hosts** (clusters A2 and B): harness bugs with nothing to change in our frontmatter. Our small auto set (about 800 tokens) keeps us low-cost.
- **Portability of Claude-only keys** (cluster L): the README scopes the pack to Claude Code, so this is not a defect. Note it only if we ever claim Codex or Cursor support.
